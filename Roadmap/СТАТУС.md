Если среди призов есть награда с кодом: прокрутка запрещена при активном коде и доступна только по одной (`count > 1` отклоняется). Закрывает пункт «один активный код при batch-spin».

### PR #11 — авторизация админки (`fc319dd`)

`app/rate_limit.py`: `AttemptLimiter`, 10 попыток за 15 минут на пару «IP + логин», дальше `429` с `Retry-After`. Кука сессии теперь содержит срок жизни и отпечаток пароля: смена пароля мгновенно обесценивает выданные сессии. Закрывает «rate-limit логина» и «отзыв сессий после смены пароля».

### PR #12 — фронт админки (`2b7143c`)

Различаются 401 и обрыв связи (авторетрай каждые 5 с), кнопки блокируются на время запроса, необратимые действия спрашивают подтверждение, очередь подтверждения постранично по 25, появилась смена собственного пароля. Закрывает «пагинация очереди».

### PR #13 — деньги: идемпотентность и уникальность кодов (`137d073`)

- `pts_transactions.idem_key` — уникальный индекс в БД; повторное начисление с тем же ключом возвращает старую транзакцию, а не создаёт вторую.
- Гонка перехватывается через SAVEPOINT + `IntegrityError`, а не только предварительный SELECT.
- Код награды вставляется с ретраем на коллизию (до 8 попыток).
- `achievements.claim` больше не падает на награде в 0 PTS.
- `schema_sync` умеет создавать индексы (`sync_sqlite_indexes`), а не только колонки.
- Ключи: `wheel_spin:{user_id}:{клиентский}`, `wheel_prize:{spin_id}`, `wheel_refund:{spin_id}`, `reward_redeem:{user_id}:{клиентский}`, `reward_refund:{code}`, `achievement_claim:{progress_id}`.

### PR #14 — `Idempotency-Key` от клиента (`582d89a`)

Мини-апп генерирует ключ на каждое денежное действие и держит его на кнопке до успешного ответа. `POST /api/wheels/spin` и `POST /api/rewards/redeem` принимают заголовок `Idempotency-Key` (санитайз + лимит 64 символа) и пробрасывают его в сервисы. Повтор запроса после обрыва сети больше не списывает ставку второй раз. Закрывает пункт «ключи идемпотентности HTTP».

### PR #15 — защитные заголовки (`f672d15`)

Middleware `security_headers` в `app/main.py`: CSP для страниц (`script-src 'self' https://telegram.org`, `object-src 'none'`, `frame-ancestors` только Telegram), строгая `default-src 'none'` для `/api/`, плюс `nosniff`, `Referrer-Policy`, `Permissions-Policy`, COOP и HSTS вне локальной среды. SRI на `telegram-web-app.js` не вешаем сознательно: Telegram обновляет файл по тому же URL, и фиксированный хеш однажды положит мини-апп.

## Что осталось открытым

По убыванию приоритета:

1. **Alembic + Postgres.** `app/schema_sync.py` — временная мера: только SQLite, только `ADD COLUMN` и `CREATE INDEX`. Любое переименование или смена типа потребует ручной миграции.
2. **Полноценный outbox Google Sheets.** Сейчас claim/unclaim внутри запроса; нужна таблица заданий с ретраями и фоновым воркером.
3. **`notify()` на события.** Гость не получает сообщений о подтверждении кода, сгорании кода и засчитанном реферале.
4. **Атомарные границы аудита.** `audit.log()` делает `flush()` в той же транзакции: если ручка падает после записи, журнал тоже откатывается.
5. **Второй владелец и восстановление доступа.** Сейчас потеря единственного пароля владельца решается только через базу.
6. **Лимитер входа в Redis.** `AttemptLimiter` живёт в памяти процесса — при нескольких инстансах лимит размножается на их число.
7. **Дедуп минут по `oasys_session_id`**, HMAC вебхука, изоляция `club_id`, тикающий таймер кода в мини-аппе, деньги как `Decimal`, `SecretStr`, смена группы 1 января.

## Ручная проверка после деплоя

В боевом SQLite-файле:

```sql
PRAGMA index_list(pts_transactions);   -- ждём ix_pts_transactions_idem_key с unique=1
PRAGMA index_list(game_sessions);      -- ждём uq_session_per_club
```

Если индекса `ix_pts_transactions_idem_key` нет, значит `init_db()` не отработал — идемпотентность без него держится только на SELECT и теряется под гонкой.

В браузере после выкатки PR #15 — открыть консоль и убедиться, что нет сообщений `Refused to load…`.

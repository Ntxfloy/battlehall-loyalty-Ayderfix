## Часть 2 — API / auth / вебхуки

**Сделано**

- права вместо голого `require_admin` на чувствительных ручках
- `webhook_token` не выдаётся в списке клубов
- `/api/console/test/*` закрыт правом и выключен в prod
- `link-phone` возвращает 409, если номер занят
- `/health` = `{"status":"ok"}`
- CORS / no-cache только локально
- демо-гейт: `safe_redirect` + `html.escape`
- PTS админки в JSON-теле
- безопасный разбор JSON на клиенте
- схемы ограничивают длину `session_id`, телефона, `client_id`, паролей и кодов
- схемы не принимают неизвестные `kind`, `rarity`, `payout_unit`; отрицательная выплата запрещена

**Открыто:** rate-limit логина, отзыв сессий после смены пароля, регистронезависимый логин, изоляция `club_id`, HMAC вебхука, CSP.

## Часть 3 — сервисы

**Сделано**

- атомарный `pts._change_balance` через `UPDATE … RETURNING`
- `EARNED_REASONS` + отдельная причина `WHEEL_PRIZE`
- `expire_due` условным UPDATE, без двойного возврата
- reject истёкшего `submitted`-кода возвращает PTS
- реферал через `increment`, а не `mark_completed`
- отсутствие `special_referral` не откатывает сессию
- взаимные и цепочечные рефералы блокируются
- реферальный код: ограниченное число попыток и читаемый алфавит без `0/O/1/I`
- реферальная сводка считается SQL-агрегацией
- неактивная/удалённая награда на ленте → возврат прокрутки
- неизвестный/битый тип приза из БД → возврат прокрутки
- нулевая стоимость ленты блокируется на runtime-пути
- `spin_id` возвращается после `flush`, больше не `null`
- `wheel.stats` отдельно считает рублёвую стоимость наград
- Sheets: `RAW` + захват строки (claim/unclaim)
- `IntegrityError` на повторном `start_session`

**Открыто:** полный outbox Sheets, ключи идемпотентности HTTP, дедуп минут по `oasys_session_id`, один активный код при batch-spin, атомарный аудит, `notify()`.

## Часть 5 — бот / сессии / seed / админы

**Сделано**

- реферальный `/start` просит телефон
- бот нормализует телефон и объясняет конфликт занятого номера вместо падения `IntegrityError`
- гонка создания Telegram-пользователя получает fallback на уже созданную запись
- `IntegrityError` на идемпотентности сессии
- потолок длительности сессии 24 часа
- `ended_at` не может быть раньше `started_at`
- слабый `ADMIN_DEFAULT_PASSWORD` в production не создаёт владельца
- `__test__ = False` на схемах `TestSession*Request`
- удаление администратора мягкое: запись и авторство сохраняются, права очищаются, cookie отзывается через `is_active`
- ID удалённого администратора не переиспользуется новой учёткой SQLite

**Открыто:** вызовы `notify()`, Alembic, второй владелец/восстановление доступа, async-доступ к БД в боте, единый get-or-create пользователя.
